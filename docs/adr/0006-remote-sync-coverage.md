# ADR 0006 — 远程同步按点位选机制，以覆盖矩阵验收

- 状态：**已采纳**（2026-10-28，P7 重启 §1；实施按 `GOAL.md` §4 逐点推进）
- 否决的草案：分支 `explore/p7-failed-client-vanilla-execution` 上的 `docs/adr/0006-client-vanilla-execution.md`（“复制决策 + 跑原版执行层 + 收束结算”，一次性取代 P2 / P6 呈现方法论），失败原因见 `docs/kb/net-facts.md`「P7 复盘」
- 保留：ADR 0005 第 3 条（Host 权威、guard、六适配器）、需求树 §7.17（P2）与 §7.20（P6）的现有通道

## 背景

P6（`4972eb0`）的 Client 呈现是“接管冻结 + 快照状态 + 产物事件复制”：敌人 / 莉莉副本按白名单冻结组件，位置 / HP / 轨道 0 动画名来自快照，技能 / 特效 / 音效 / 技能结束 / 受击由 Host 在原版入口捕获后在 Client 同入口重放。缺口是开放集合（附着 / 循环音效、蓝图直生特效、VisualPivot、伴随精灵……）。

P7 试图用“复制 CommandQueue 命令启动沿 + Client 跑原版执行层 + 结算汇点做减法”一次性替换它，并在同一阶段删除了 P6 通道。同一剧本 A/B（net-facts「P7 复盘」）：动画变化沿按序匹配从 P6 的 90%（195/217）降到 45%（140/313）——敌人缺全部不经命令的状态（`idle_turn`）、攻击循环分叉（命令 304/304 到达仍 7 vs 5）；Host P1 副本缺跳跃 / 闪避 / 全部受击击飞、HP 不更新；坐椅休息、配装等不在命令管线上的状态要逐个打补丁（`hold_host_pose`、`SeatBuild`）。方向的一部分成立（原版执行层能完整产生表现），错在没有逐点位证据就对全部对象换方法论、删兜底。

## 决定

1. **同步点位是基本单位。** 每个点位（例：“远程莉莉 · 受击击飞”“敌人 · 附着音效”“世界 · 宝箱打开”）在 `docs/kb/sync-coverage.md` 占一行，列 Host 源头（原版入口 / 字段 + 证据标签）、当前状态、机制、Client 验证方法、最近实测。
2. **机制清单**——每个点位从下面选一种（可组合，但每种都要有证据）：
   | 编号 | 机制 | 适用条件 | 已有载体 |
   |---|---|---|---|
   | ① | **快照状态**（位置 / 朝向 / HP / 轨道 0 动画名 + 时间 / 可见 / 标志位） | 状态可读、可幂等写入；Client 收敛靠每帧覆盖 | 快照段 `l / e / ed / w / pk / sp`（`net/snapshot.h`）、`Taken` 插值、`SetAnimation + SetTrackTime` |
   | ② | **事件复制**（Host 在原版入口 pre 取参 → Client 对呈现对象调同一入口） | 一次性产物：技能、特效、音效、技能结束、受击表现；入口唯一、参数可序列化、Client 侧调用无结算 | `Act / Fx / FxStop / Snd / ActStop`、`Ref`、300 ms 乱序重试 |
   | ③ | **决策复制**（命令启动沿 → Client `AddNewImmediateCommand`） | 仅当：该对象 / 命令类的执行层在 Client 可无副作用跑完；结果被 ① 每帧纠正；执行依赖的本地状态（着地、配装、连段计时）已证明一致或无关 | 暂无（P7 的命令通道不并入 main） |
   | ④ | **放开部分执行层**（按组件 / 按命令类不冻结） | 仅当：该部分在 Client 可达的全部结算汇点已 IDA xref 到底、每个汇点有拦截与计数（engine-facts「结算汇点」）；Client 状态被证明收敛到快照 | 暂无 |
   | ⑤ | **不同步** | 技术不可行 / 需要用户存档 / 产品决定；写进 README 已知限制并附理由 | — |
3. **选择准则**（按顺序问）：
   1. 这是结算吗（伤害、死亡、清除、掉落、存档、交互、奖励）？→ 只在 Host；Client 只经 ① 呈现结果。
   2. 状态能从 Host 读出、在 Client 幂等写入吗？→ ①（默认）。
   3. 是一次性产物且有唯一原版入口吗？→ ②。
   4. ① ② 都做不到或代价过高（开放集合、每帧上百事件）时，才评估 ③ / ④，并先完成该点位的结算汇点枚举与收敛证明，写进 kb。
   5. 都做不到 → ⑤，理由进 README。
4. **兜底不删。** ① 的快照动画 / 位置 / HP 写入对所有呈现对象保留；任何点位换机制后，旧通道保留到该点位所在剧本与正确性行在矩阵上全绿为止；删除通道必须单独提交并附矩阵前后对照。
5. **不整体换方法论。** 一个点位的实现不得改变其他点位的呈现方式（例：为了“副本跳跃”不得取消副本的快照动画）。
6. **验收**：每个点位 = 调研（IDA / CUE / 实例证据）→ 实现 → 重跑受影响剧本（`tools/scenario.py`）+ `tools/sync_diff.py` + 两侧截图 + 正确性行（Client 结算泄漏 0、敌人数量 / HP 全等、Client `Saved/` 哈希不变）+ `elmp perf` P99 < 1 ms → 矩阵该行改“已同步”→ 一点一提交。

## 后果

- 正面：覆盖率可度量、可回归；每一步不降低正确性；P6 的兜底继续保护未改造的点位。
- 代价：② 的开放集合仍需逐项补（附着音效、蓝图直生特效等各一条入口）；每个点位都要做对账与截图，进度比“一次换方法论”慢。
- 风险：某些点位 ① ② 都不可行而 ③ / ④ 的结算证明成本很高 → 允许标 ⑤ 并写已知限制，不硬上。

## 被否决的草案（分支 ADR 0006，2026-10-28）

“复制决策 + 跑原版执行层 + 收束结算”对**所有**网络对象一次性实施，并删除 P6 通道。保留其中经证实的事实（engine-facts「CommandQueue 决策管线」「结算汇点」，net-facts「命令注入与输入驱动实验」）；否决其方法论范围：不经命令管线的状态（转身、受击、坐椅、配装）无法到达，命令重放在本地状态不同的对象上分叉，且删除兜底后没有回归基线。③ / ④ 作为本 ADR 机制清单中的条件选项保留。
