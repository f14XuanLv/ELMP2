# ADR0015：未封口是回放等待，不是因果错误（2026-11-08）

状态：已实施；旧版隔离复现，新版通过暂停/恢复、GT停顿与重复召唤回归。

对应 F2.4/F2.5、X-1，修正 ADR0011 的超时分类。Client 日志 01:39:45 记录 `causal fence not ready: playback=97415450.392 fence=97415448`，随后主动退回标题；Host 收到明确的离会消息，双方进程仍在。日志中的 root/target 零值是无缺失引用时的诊断占位，不证明存在坏目标。仅凭这段日志不能证明用户当时做了哪一个操作。

现有 Host 在没有事实、角色帧或活跃根时不发送 LilyCauses。最后一个 LilyFrame 的回放区间可以延伸至采样时间之后，空闲/暂停时可能等待下一次封口；此前与缺失目标共用的 1 秒计时器会将等待升级为离会。这是同步边界的活性策略错误，不能用增加毫秒容差、伪造帧或放开 Client 结算处理。

决定：

1. 对地图/视图已就绪的 peer，每轮采集结束后均发送原有 LilyCauses，事实集合可以为空。它只承诺截至封口的事实已经发送，不代表角色/世界推进。仍在同一可靠有序通道，先事实后对应角色帧；协议14格式不变。
2. `ready` 在 Host 尚未封口到请求时间时返回 false，消费者保留队列并停止原版回放。未封口本身不启动因果故障计时器。会话仍由现有传输无响应/可靠通道无进展的 8 秒超时处理真实断线，不在回放层再造更短的网络故障判据。
3. 封口已经覆盖而必须使用的目标仍无法解析时，保留原有目标等待/故障和精确引用诊断；缺失 Query、身份冲突、未知来源与容量错误仍拒绝。客户端不重新本地选敌，不补结算。
4. 审计增加封口等待次数、最大超前毫秒及最后封口接收距今时间；会话/地图清理与原事实账本一起重置。不会逐帧刷日志。

验证以隔离实例暂停/恢复、重复召唤结束后空闲、双端持续连接和故障状态为准，保留正常原版命令/查询/清理的实测。不能用只有无故障的空场景替代真实等待路径的证据。结果见[本轮 kb](../kb/causal-fence-wait-2026-11-08.md)。
