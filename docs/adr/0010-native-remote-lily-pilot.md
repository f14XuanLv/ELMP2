# ADR 0010：远端莉莉原版执行试验

- 日期：2026-11-05；状态：采纳为快速实机试验，效果由用户双窗口游玩验收。
- 用户要求删除可替换的旧实现，再以原版入口重写、编译部署 Host/Client。

远端 Lily 不再冻结后复制 Spine 轨道、Visual 组件与每个 Spirit/Companion。Host 在真实 InputConsume 后捕获完整输入及消费序号，带运动位置/速度/模式和当前 State 上下文可靠投递；Client 为同图非自己座位创建已 Possess 的 Lily，经 core/profile 的原版库存/装备入口建立装备、Spirit 与 Companion，随后让原版角色、命令队列、五时间线、召唤及动画组件执行。每次消费只使用一份有序输入，无输入时暂停该副本的时钟；不把最新状态包反复制造为按下沿。装备基线与变化通过可靠消息发送，创建/换图先完成装备上下文。

同一来源取消旧 Lily Pose/Visual 应用、Spirit/Companion 裸副本、Act/Fx/Snd 复制；敌人仍沿现有通道。原版伤害、Effect Apply/Finalize、死亡结算和保存闸门继续生效；远端角色关闭 overlap，保留原版运动所需的阻挡检测，并屏蔽交互输入，避免新增本地世界副作用。Host 实际受击反应扩展到远端角色，仍调用原版入口，不广播伤害委托。

换肤使用显式 FSpineDataGroup 的原版 SetSpineData，读取对应 DataTable 行并按 FProperty 深复制；不调用固定读取 P1 等级的 RefreshSpineData。

此试验不宣称输入能覆盖全部外部原因。Homing 查询、晚加入进行中的动作、原版单例剧情/椅子及两端帧相位仍须实机记录；不将构建/连接成功当作表现验收。原版生成的对象由其 PC/装备/命令拥有，换图/离会沿原版清理，不逐行 DestroyActor。协议升级拒绝旧端。

缓存：每个 seat 的 Pawn weak serial、可靠输入 FIFO（最多120帧）、装备内容/代次、输入消费序号；Pawn替换、图代次、离会清理。观察指标包括 received/consumed/queued/profileApplied/fault；溢出、未知状态、装备失败显式结束会话。

首轮实机发现两进程帧率小差异会使一帧一份输入的 FIFO 持续增长。改为预检过的 AZenithCharacter::Tick 接缝逐份调用原版（每渲染帧最多4份、保留2份缓冲），不跳过按下沿；组件按消费时长合计推进。Host 同接缝记录角色实际 delta。位置/状态在对应消费之前设置，未收到输入时不额外推进角色命令。

2026-11-06 平滑度修正：上述整数份追帧导致组件时钟0/1/4倍跳变，短测整帧P99约16.8ms而组件倍率P99=4、最高8，不能继续使用。改为50ms目标的连续时间缓冲；按Host世界帧时长消费时间，速率缓慢调整且限制0.9–1.1，每个输入边沿只在首次进入该Host帧时交给原版。必要的原版Tick分段之和等于组件本帧的推进时长，不再以包数设置组件时钟。协议同时传世界帧时长与角色实际delta，保留原版HitStop的有意减速。位置/速度上下文在播放游标处插值，每渲染帧只校正一次，小误差渐进修正、大传送立即校正。可靠输入不丢弃；真实断流仍允许耗尽缓冲，暴露饥饿计数，不能伪造新的按下沿。装备/权限职责不变。

新增原版角色detour耗时、组件倍率、缓冲时长、位置误差、饥饿与按下沿计数；旧frame.elmp_us不含原版detour及引擎组件，因此性能验证同时保留FrameProbe整帧结果。缓存仍按Pawn/地图/会话失效，FIFO仍为120帧上限。

网络接收同时处理突发：UDP接收缓冲扩至1MiB，非阻塞接收在每次网络轮询中有界排空最多256个数据报，再统一ACK和发送。新增可靠60Hz输入不能依赖旧latest-only快照可容忍的丢包行为；本机长测已观察RTT仅约2ms却有频繁重传和百毫秒级排队，修正必须以实际socket收发复测，不以纯Link状态机测试代替。

切图长帧另作时基修正：UEngine::Tick的delta不等于UWorld本轮组件delta（World会限幅/缩放）。Host在原版InputConsume读取GetWorldDeltaSeconds；Client在角色原版Tick接缝读取当前World delta后调度时间分段和组件倍率，EngineTickPre只负责接收/装备准备。不可用Engine delta推算组件倍率，也不可将切图长帧误判为坏包。有限非负角色delta、正World delta上限60秒，超界显式报出实际数值。

Host长帧恢复：角色实际delta原样保留；播放间隔以最近31个World帧时长的中位数为节奏，单个Host长帧的播放间隔至多为中位数的1.5倍。Host已经发生的停顿不能在Client缓冲中再重放一次几百毫秒的等待；压缩的仅是网络播放间隔，不丢该帧输入/状态或原版执行时长。该情形组件可短时按Host实际长帧推进，区别于普通数据包成批到达引起的0/4倍抖动。每seat的31项时长窗口随Host启停、Pawn serial变化失效，暴露压缩次数。
